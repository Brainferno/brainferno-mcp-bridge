# Spike 12 — Illustrator (Beta) MCP: live sweep of all 46 tools

Date: 2026-08-28. Every one of the 46 tools exposed by Adobe's built-in Illustrator (Beta) MCP server (`http://localhost:18412/v1/mcp`) was called at least once through adobe-cc-mcp's pass-through (`ai_beta_call` / `ai_beta_status`) against a prepared 800×600 pt RGB document (`beta-sweep.ai`: five PathItems and one TextFrame on one layer). No tool reports the Illustrator version explicitly; the only hint is CapturePreview's fixed output folder `~\AppData\Local\Temp\AI_30_9\`, i.e. an Illustrator 30.x build. `ai_beta_status` reported `{available:true, toolCount:46}` throughout. Result: 35 ok, 10 ok-with-quirk, 1 error (Vectorize, expected — the document has no raster image). Nothing was closed; the six original objects survived intact and were verified with a final `GetCanvasStructure` and a preview.

## What this means for callers

- **Get UUIDs first.** Every object tool needs UUIDs from `GetCanvasStructure` (layer view) or `GetArtboardStructure` (per-artboard, includes `is_selected`). UUIDs are small integer strings (`"473"`), assigned per session — never cache them across document open/close.
- **`uuids` is always an array**, even for one object, on every batch tool; `RenameObject` uses parallel `uuids`/`newNames` arrays. Only `Vectorize`, `ReplaceText` and `CreateClippingMask.maskUuid` take a scalar `uuid`.
- **Coordinates are canvas-global points, Y-down, bounds `[left, top, right, bottom]`.** The origin is wherever the document put it: this ExtendScript-created doc had artboard 1 centred on (0,0) (`[-400.5,-300.5,399.5,299.5]`), while `CreateDocument` makes `[0,0,w,h]`. Always read the artboard bounds before computing positions. Relative moves: +y is down; rotation: +angle is counter-clockwise.
- **Colours are asymmetric**: you *send* hex `#RRGGBB`, you *receive* `{model:"RGB", red, green, blue}` as 0–1 floats.
- **Artboard mutators are prose-only.** `CreateArtboard`, `DuplicateArtboard`, `FitArtboard`, `SetArtboardProperties`, `SetActiveArtboard` return `{success, details, uuid:""}` with the new index/bounds embedded in the `details` sentence. `ScaleArtboards`, `MoveArtboards`, `DeleteArtboard` do return the full `artboard_details` list. After Create/Duplicate, call `ListArtboards` rather than parsing the sentence. Indices are 1-based and re-number after a delete.
- **`CreateClippingMask` (and by the same rule `CreateGroup`) default to the front of the *document*, i.e. the topmost layer.** Pass `parentID` (the source objects' layer or group) or the artwork silently migrates layers.
- **Success does not mean change.** `CleanupPath` returned success with `pointsBefore == pointsAfter`; `OpenDocument` on an open file "succeeds" by switching. Read the numeric fields / `details` to know what actually happened.
- **`Export` in `stream` mode returns two content parts** (raw SVG/PNG data, then a JSON status). File mode returns the path in `~\`-abbreviated form; `collisionStrategy` defaults to `error` so pass `overwrite` for re-runs. `resolution:72` on an 800×600 pt artboard gives exactly 800×600 px.
- **`CapturePreview` writes one fixed file** (`~\AppData\Local\Temp\AI_30_9\illustrator_preview.png`) and returns no image bytes; read it before the next call overwrites it. adobe-cc's own `ai_get_preview` is the more convenient way to look at the artboard.
- **`Vectorize` refuses non-raster targets with a clean error** — no dialog, no side effects. `DuplicateArtboard(duplicateContent:true)` and `FitArtboard` both use "intersects the artboard" semantics, so stray objects that overlap the board get included.
- Every call in this sweep returned in well under a second; nothing opened a dialog or blocked the UI.
