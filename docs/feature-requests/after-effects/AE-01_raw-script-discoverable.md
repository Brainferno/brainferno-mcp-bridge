# AE-01 — Raw script access that clients can discover, plus `ae_run_script`

## Problem
An MCP client building many layers, masks, and expressions had no way to run a multi-step ExtendScript in one call, so it needed hundreds of tool calls. A raw-script tool existed (`cc_eval_script`), but the client never saw it. X-01 fixed the discovery half:
- Since X-01, `cc_eval_script` is always registered and refuses while its gate is closed; `cc_get_capabilities` shows the gate per app. (Before X-01 it was absent from the tool list unless `BRAINFERNO_MCP_ALLOW_RAW_SCRIPTS=1`, the only hint an info line on stderr.)
- Since X-01, the raw-script contract lives once in `packages/server/src/tools/raw-script.ts`: the envelope, the ES3 wrapper (`__log`, the plain-data check, `bodyLine`), the gate (`rawGateState`), the refusal texts and the audit line (`auditRawCall`). `ae_run_script` reuses all of it — it re-implements none of it (`CONTRIBUTING.md`, "Raw-script tools — one contract").
- Still open: `cc_eval_script` takes an `appId`; there is no After Effects–specific tool, and its description cannot explain AE conventions (undo group, project open, dialogs).
- Still open: a raw script is not yet one After Effects undo step — the X-01 wrapper opens no undo group, so a script that makes ten changes takes ten Ctrl-Zs. `ae_run_script` adds the undo group.
- The client also tried to launch a script from the command line (`AfterFX.exe -r <file.jsx>`); it exited with code 0 and ran nothing. The MCP route was the only option, and it was invisible.

## Add
1. **Gate and refusal: reuse X-01.** `ae_run_script` is registered unconditionally, checks `rawGateState("after_effects", …)` before touching the bridge, and refuses with the shared text (`RAW_SCRIPTS_DISABLED_MESSAGE`, which `rawScriptsDisabledMessage` extends with the target app and the enabled list). Never write a second refusal string. (As built: `registerAfterEffectsTools`' options gain three required fields — `rawScriptApps`, `remote`, `allowRemoteRawScripts` — that `server.ts` passes, as Photoshop's do; that is a shared-core change for the architect. The tool registers whenever After Effects' tools do, as `ps_batch_play` does with Photoshop's, so the "app not enabled" refusal cannot be reached from it.)
2. **`ae_run_script`** — After Effects raw script with AE-aware behavior.
   - Inputs: `script` (string, ES3, one IIFE or a statement list — state which in `.describe()`), `args` (object, optional, exposed to the script as `__args`), `undoGroupName` (default `"Brainferno script"`), `suppressDialogs` (boolean, default `true`), `timeoutMs` (optional; default from config). (As built: `args` is plain JSON data at most 32 levels deep, sent as a pure-ASCII ES3 literal built by `aeArgsLiteral` in the outer IIFE, never inside the wrapper's `__src`; deeper data, a number that is not finite, a sparse array, an object that is not plain or a nested `__proto__` key is refused as plain text before dispatch, and zod drops a top-level `__proto__`. `undoGroupName` takes 1–200 characters. `timeoutMs` is capped at 30 minutes, as `cc_eval_script`'s is; there is no job path, because nothing can cancel a running ExtendScript.)
   - Runs the caller's script through `rawScriptWrapper` inside `app.beginUndoGroup(undoGroupName)` / `app.endUndoGroup()` (end it in a `finally`), so one call is one Ctrl-Z — the part X-01 does not do. (As built, `runRawScript` in `after-effects.ts`:
     - The wrapper runs inside a local `__undo(undoGroupName, fn)` that closes the group whether `fn` returns or throws; with `suppressDialogs`, `app.beginSuppressDialogs()` / `app.endSuppressDialogs(false)` sit inside it, ended the same way. Each begin call sits before its `try`, so a begin call that fails is never followed by its end call.
     - Each end call has its own try/catch and runs after a catch, not in a `finally` (under ES3 a `finally` cannot see the throw, and a throw from it replaces the original). A failure after a result is reported in the envelope's `error.message` ("`app.endUndoGroup() failed: … — the script ran; check After Effects before re-running.`", after the script's own error if it had one) and the script's value and logs are kept; it never replaces the result. A failure after the call itself threw (the wrapper or a begin call) is appended to the thrown message ("`… app.endUndoGroup() failed: … — check After Effects before re-running.`"), rethrown as a plain object with no line, and reaches the caller as the dispatched envelope; a throw no end call added to is rethrown as it was.
     - The tool owns both pairs, so a script that names `app.beginUndoGroup`, `app.endUndoGroup`, `app.beginSuppressDialogs` or `app.endSuppressDialogs` — even in a comment or a string — is refused as plain text before dispatch, with one `outcome=refused` audit line: a caller's unbalanced pair could not be repaired from outside.
     - `alert`, `confirm` and `prompt` are shadowed by shims that fail the call instead of opening a modal dialog. A shim throws a plain object, so `line` and `bodyLine` are `null`, and its message ends with its own next step: `use __log(msg) instead.` for `alert`; `pass the answer in args and read it from __args.` for `confirm` and `prompt`. The shims stop only a bare call written in the script's own text (whose scope chain runs through the outer IIFE). `Window.alert`, `$.global.alert`, `this.alert`, a `$.evalFile`'d library or a global helper that calls them, ScriptUI dialogs and file or folder pickers still open a modal dialog; the `script` parameter's text says so.
     - Opening, creating or closing a project, or importing an `.aep`, inside the script resets or breaks After Effects' undo history, so the description carves those calls out of the one-Ctrl-Z promise. The `script` text adds that the promise covers project edits only: what the script saves or writes (`app.project.save`, files, renders, preferences) stays changed.)
   - Returns: the X-01 envelope `{ ok, error?, durationMs, value, logs, logsDropped? }` (`toEnvelope` / `envelopeResult`); `logs` collects `__log(msg)` calls.
   - Errors: `{ message, line, bodyLine }` as the wrapper computes it; if `ae_run_script` adds code around the caller's text, make sure `bodyLine` still points into the caller's script (see X-01's `rawScriptWrapper` / `toEnvelope`). If `ae_run_script` registers inside `registerAfterEffectsTools`, keep its name in `AE_NO_ARG_ECHO` there (AE-16 put it in already) so the error context never echoes the script text. Dispatched failures go through `dispatchedFailure` (JSON envelope); not-dispatched ones stay plain text. (As built: `toEnvelope` gets the caller's script, and everything added — `__args`, the shims, the undo and suppression calls — sits outside `__src`, so `bodyLine` counts the caller's lines. `AE_NO_ARG_ECHO` hides only the arguments; the script stays out of error text because `dispatchedFailure` keeps the host's message without AE-16's context, and AE-16 never locates `runRawScript`'s output as a typed tool's body.)
   - Annotations: `destructiveHint: true`; `timeoutClass: "slow"`. Same gate as `cc_eval_script`. (As built: annotations `{ destructiveHint: true, openWorldHint: true }`; `timeoutClass: "slow"` is an `EvalOptions` value passed to `evaluateAe`, not an annotation.)
   - Audit every call, run or refused, with `auditRawCall`. (As built: the payload is the JSON of `{ script, args }`, `args` `{}` when left out, built by `auditJson`, a new export of `raw-script.ts` that never throws, so a call whose `args` are too deeply nested for `JSON.stringify` is still audited once.)
   - (As built, beyond this list: `cc_get_capabilities` has an `ae_run_script` row, `cc_eval_script`'s description points After Effects work to `ae_run_script` (when After Effects' tools are enabled), and its `script` parameter says how to return an object literal. Both are in `tools/diagnostics.ts`, a cross-app file to call out.)
   - (As built: Claude Code shows only the first 2,048 characters of a tool description. `ae_run_script`'s description holds the safety text within that, in this order: what the tool does and the one undo step, the error-shape rule, the modal-UI warning, the project switch (the auto-save hazard the live runs found, scoped to the calls it was seen with — `app.open`, `app.openFast`, `app.newProject` — and the operator's OK in the chat), the gate, the envelope. The detail — the ES3 rules, the object-literal note, the undo carve-out's wording, the managed calls, which dialogs the shims do and do not stop, when `bodyLine` is null — is in the parameters' texts. `server.test.ts` checks every tool's description and parameter texts against the limit.)
3. **Project-switch OK** (owner request 2026-10-12; chat only by the owner's decision of 2026-10-12). With suppression on, a script that opens another project with `app.open` saves the open one's unsaved changes over its file (acceptance 9 below; spike 06's "AE-01 probe 10"), and `CloseOptions.DO_NOT_SAVE_CHANGES` throws them away (seen live in the consent run on a project with a file, T5on); either can lose the operator's work. So a script that closes or replaces the open project needs the operator's OK, given in the chat and never asked in After Effects. (As built; a plain-text refusal and a flagged run were seen live on an earlier build (acceptance 12), whose refusal had older wording and whose flag ran with no refuse-first guard; the guard, the current refusal text and the risk texts are unit-tested only:
   - The trigger: `projectSwitchCalls` scans the script's text, case-sensitive, for `app.open(`, `app.openFast(`, `app.newProject(`, `app.project.close(`, `app.quit(`, `app.restart(` and the word `CloseOptions` (an alias of `app.project` that closes); each name may be reached with a dot or as a whole quoted name in brackets (`app['open'](`, `app["project"]["close"](`), whitespace around the dots and brackets and before `(` counts, and so do comments and strings. Not caught, among others: a computed name (`app["op" + "en"]`, `app[name]`), an alias of `app` or of the method, `with (app) { open(f) }`, `(app).open`, `.call`/`.apply`, a comment or escape inside the call, a menu command run by id, and code run from elsewhere at run time (`$.evalFile`, `eval` of a file's text or of text passed in `args`): a guard against honest mistakes, like the managed-call refusal. The full list is the regex's comment, which T2 pins gap by gap.
   - The order after the managed-call refusal: the scan; the refuse-first guard; on a first call, the read-only check (`PROJECT_INFO`, `ae_project_info`'s script, `timeoutClass: "fast"`; After Effects not connected is the usual plain text, and any other failure refuses with nothing recorded) and the refusal; on an approved call, the `run` audit and the dispatch. Nothing is skipped as provably harmless: the script can make the project dirty itself before it switches.
   - The refusal (`switchRefusal`): plain text naming the calls and their lines (never script text), the file name and path (or "never saved"), whether there are unsaved changes right now, and what After Effects does with them for each call (`riskSentence`), from the consent live run's table: a seen outcome as fact, an expected save prompt as expected, anything not tried as "not verified live". A close counts as one `CloseOptions` value only when its own argument is that value written out (`closeOptionsOf`); any other close gets each value's outcome. With two switch calls or more it adds that each clause describes the project open now and the later calls act on the project the first leaves open. It says the approved call does not read the project again (so if it changes first, call without the flag for a new refusal). It tells the model to tell the operator, ask in the chat, and call again with the same script, `args` (as sent) and `suppressDialogs` plus `allowProjectSwitch: true` only if they agree, or to remove the calls; it says not to route the script through another tool, and in a shared session that the person in the chat answers for whoever is at After Effects.
   - The refuse-first guard (`SwitchRefusals`, one per `McpServer`, so per session): each refusal records the call's key (the SHA-256 of the audit payload — `args` as sent, `{}` when left out — and the effective `suppressDialogs`; at most 64, each for 10 minutes, on an injectable clock). `allowProjectSwitch: true` runs the call only when its key is recorded, and uses it up (one OK, one run), without a second read-only check; it is taken when the call starts and put back only when After Effects was not connected. No flag, or `false`, never runs it. A flag with no matching refusal gets the refusal, with one sentence more in front. A failed check, or a call the client cancelled during it, records nothing. The server cannot tell whether the operator was asked: the guard only makes sure the refusal, with the risk, reached the model first; the asking happens in the chat, where the operator can see the model's tool calls. A session is one MCP connection: in Claude Code, a window's subagents and its conversations after `/clear` are expected to share the store (not verified live). No MCP elicitation: in the live check Claude Code 2.1.296 in a Windows 11 terminal, in three tries (auto mode twice, manual once), advertised form elicitation, did not show the question, and answered `accept {allowProjectSwitch: false}` by itself (no Elicitation hook in user or project settings; managed settings not checked conclusively), so a client that "can ask" gets the same refusal.
   - `cc_eval_script` refuses such an After Effects script as plain text and points to `ae_run_script`, so there is one consent path; other apps are unchanged.
   - The audit line gains `consent=needed` on the refusal and `consent=flag` on the run after it; every other line is unchanged.)

## API hints (ES3)
- `app.beginUndoGroup(name)` / `app.endUndoGroup()` — one script = one Ctrl-Z.
- `app.beginSuppressDialogs()` / `app.endSuppressDialogs(false)` stops a missing-font or missing-footage dialog from hanging scripting. The existing MOGRT export already does this (see the repo's AE mogrt-export note). (As built, the tool promised less at first: Adobe documents the call for script error dialogs, and a community report said it does not cover the missing-font message shown when a project is opened. The live run on After Effects 26.5 settled it (acceptance 5): suppression hid an export warning raised by a Motion Graphics template export and the missing-font dialog when the script opened a project, and each blocked without it. The description and the `suppressDialogs` text name those two as examples of After Effects' own warning dialogs and promise no more. The same run found that with suppression on, opening another project saves the open one's unsaved changes over its file without asking: the description warns of it, and the `suppressDialogs` text gives `app.project.close(CloseOptions.DO_NOT_SAVE_CHANGES)` as the way to discard them.)
- The panel entry is `__acmEval` in `packages/panel-cep/host.jsx`; it serializes with `__acmJson`. See `AE-05` for a serializer bug on `TextDocument`. (Not reachable from `ae_run_script`: the wrapper refuses a host object before `__acmJson` runs.)
- Keep the script in one IIFE: `(function () { ... return value; })()`. (This applies to the script the builder sends; the caller's script may be a statement list.)
