# AE-01 — Raw script access that clients can discover, plus `ae_run_script`

## Problem
An MCP client building many layers, masks, and expressions had no way to run a multi-step ExtendScript in one call, so it needed hundreds of tool calls. A raw-script tool existed (`cc_eval_script`), but the client never saw it. X-01 fixed the discovery half:
- Since X-01, `cc_eval_script` is always registered and refuses while its gate is closed; `cc_get_capabilities` shows the gate per app. (Before X-01 it was absent from the tool list unless `BRAINFERNO_MCP_ALLOW_RAW_SCRIPTS=1`, the only hint an info line on stderr.)
- Since X-01, the raw-script contract lives once in `packages/server/src/tools/raw-script.ts`: the envelope, the ES3 wrapper (`__log`, the plain-data check, `bodyLine`), the gate (`rawGateState`), the refusal texts and the audit line (`auditRawCall`). `ae_run_script` reuses all of it — it re-implements none of it (`CONTRIBUTING.md`, "Raw-script tools — one contract").
- Still open: `cc_eval_script` takes an `appId`; there is no After Effects–specific tool, and its description cannot explain AE conventions (undo group, project open, dialogs).
- Still open: a raw script is not yet one After Effects undo step — the X-01 wrapper opens no undo group, so a script that makes ten changes takes ten Ctrl-Zs. `ae_run_script` adds the undo group.
- The client also tried to launch a script from the command line (`AfterFX.exe -r <file.jsx>`); it exited with code 0 and ran nothing. The MCP route was the only option, and it was invisible.

## Add
1. **Gate and refusal: reuse X-01.** `ae_run_script` is registered unconditionally, checks `rawGateState("after_effects", …)` before touching the bridge, and refuses with the shared text (`RAW_SCRIPTS_DISABLED_MESSAGE`, which `rawScriptsDisabledMessage` extends with the target app and the enabled list). Never write a second refusal string. (As built: `registerAfterEffectsTools`' options gain three required fields — `rawScriptApps`, `remote`, `allowRemoteRawScripts` — that `server.ts` passes, as Photoshop's do; that is a shared-core change for the architect. The tool registers whenever After Effects' tools do, as `ps_batch_play` does with Photoshop's, so the "app not enabled" refusal cannot be reached from it.)
2. **`ae_run_script`** — After Effects raw script with AE-aware behavior.
   - Inputs: `script` (string, ES3, one IIFE or a statement list — state which in `.describe()`), `args` (object, optional, exposed to the script as `__args`), `undoGroupName` (default `"Brainferno script"`), `suppressDialogs` (boolean, default `true`), `timeoutMs` (optional; default from config). (As built: `args` is plain JSON data at most 32 levels deep, sent as a pure-ASCII ES3 literal built by `aeArgsLiteral` in the outer IIFE, never inside the wrapper's `__src`; deeper data, a number that is not finite, a sparse array, an object that is not plain or a nested `__proto__` key is refused as plain text before dispatch, and zod drops a top-level `__proto__`. `undoGroupName` takes 1–200 characters. `timeoutMs` is capped at 30 minutes, as `cc_eval_script`'s is; there is no job path, because nothing can cancel a running ExtendScript.)
   - Runs the caller's script through `rawScriptWrapper` inside `app.beginUndoGroup(undoGroupName)` / `app.endUndoGroup()` (end it in a `finally`), so one call is one Ctrl-Z — the part X-01 does not do. (As built, `runRawScript` in `after-effects.ts`:
     - The wrapper runs inside a local `__undo(undoGroupName, fn)` that closes the group whether `fn` returns or throws; with `suppressDialogs`, `app.beginSuppressDialogs()` / `app.endSuppressDialogs(false)` sit inside it, ended the same way. Each begin call sits before its `try`, so a begin call that fails is never followed by its end call.
     - Each end call has its own try/catch and runs after a catch, not in a `finally` (under ES3 a `finally` cannot see the throw, and a throw from it replaces the original). A failure after a result is reported in the envelope's `error.message` ("`app.endUndoGroup() failed: … — the script ran; check After Effects before re-running.`", after the script's own error if it had one) and the script's value and logs are kept; it never replaces the result. A failure after the call itself threw (the wrapper or a begin call) is appended to the thrown message ("`… app.endUndoGroup() failed: … — check After Effects before re-running.`"), rethrown as a plain object with no line, and reaches the caller as the dispatched envelope; a throw no end call added to is rethrown as it was.
     - The tool owns both pairs, so a script that names `app.beginUndoGroup`, `app.endUndoGroup`, `app.beginSuppressDialogs` or `app.endSuppressDialogs` — even in a comment or a string — is refused as plain text before dispatch, with one `outcome=refused` audit line: a caller's unbalanced pair could not be repaired from outside.
     - `alert`, `confirm` and `prompt` are shadowed by shims that fail the call instead of opening a modal dialog. A shim throws a plain object, so `line` and `bodyLine` are `null`, and its message ends with its own next step: `use __log(msg) instead.` for `alert`; `pass the answer in args and read it from __args.` for `confirm` and `prompt`. The shims stop only a bare call written in the script's own text (whose scope chain runs through the outer IIFE). `Window.alert`, `$.global.alert`, `this.alert`, a `$.evalFile`'d library or a global helper that calls them, ScriptUI dialogs and file or folder pickers still open a modal dialog; the `script` parameter's text says so.
     - Opening, creating or closing a project, or importing an `.aep`, inside the script resets or breaks After Effects' undo history, so the description carves those calls out of the one-Ctrl-Z promise.)
   - Returns: the X-01 envelope `{ ok, error?, durationMs, value, logs, logsDropped? }` (`toEnvelope` / `envelopeResult`); `logs` collects `__log(msg)` calls.
   - Errors: `{ message, line, bodyLine }` as the wrapper computes it; if `ae_run_script` adds code around the caller's text, make sure `bodyLine` still points into the caller's script (see X-01's `rawScriptWrapper` / `toEnvelope`). If `ae_run_script` registers inside `registerAfterEffectsTools`, keep its name in `AE_NO_ARG_ECHO` there (AE-16 put it in already) so the error context never echoes the script text. Dispatched failures go through `dispatchedFailure` (JSON envelope); not-dispatched ones stay plain text. (As built: `toEnvelope` gets the caller's script, and everything added — `__args`, the shims, the undo and suppression calls — sits outside `__src`, so `bodyLine` counts the caller's lines. `AE_NO_ARG_ECHO` hides only the arguments; the script stays out of error text because `dispatchedFailure` keeps the host's message without AE-16's context, and AE-16 never locates `runRawScript`'s output as a typed tool's body.)
   - Annotations: `destructiveHint: true`; `timeoutClass: "slow"`. Same gate as `cc_eval_script`. (As built: annotations `{ destructiveHint: true, openWorldHint: true }`; `timeoutClass: "slow"` is an `EvalOptions` value passed to `evaluateAe`, not an annotation.)
   - Audit every call, run or refused, with `auditRawCall`. (As built: the payload is the JSON of `{ script, args }`, built by `auditJson`, a new export of `raw-script.ts` that never throws, so a call whose `args` are too deeply nested for `JSON.stringify` is still audited once.)
   - (As built, beyond this list: `cc_get_capabilities` has an `ae_run_script` row, `cc_eval_script`'s description points After Effects work to `ae_run_script` (when After Effects' tools are enabled), and its `script` parameter says how to return an object literal. Both are in `tools/diagnostics.ts`, a cross-app file to call out.)
   - (As built: Claude Code shows only the first 2,048 characters of a tool description. `ae_run_script`'s description holds the safety text within that, in this order: what the tool does and the one undo step, the error-shape rule, the modal-UI warning, the gate, the envelope. The detail — the ES3 rules, the object-literal note, the undo carve-out's wording, the managed calls, which dialogs the shims do and do not stop, when `bodyLine` is null — is in the parameters' texts. `server.test.ts` checks every tool's description and parameter texts against the limit.)

## API hints (ES3)
- `app.beginUndoGroup(name)` / `app.endUndoGroup()` — one script = one Ctrl-Z.
- `app.beginSuppressDialogs()` / `app.endSuppressDialogs(false)` stops a missing-font or missing-footage dialog from hanging scripting. The existing MOGRT export already does this (see the repo's AE mogrt-export note). (As built, the tool promises less: Adobe documents the call for script error dialogs; it is verified on the save and Motion Graphics template export path (`docs/quirks/ae-mogrt-export.md`); a community report says it does not cover the missing-font message shown when a project is opened. The description and the `suppressDialogs` parameter promise only After Effects' script warning and error dialogs, such as those raised while saving or exporting, and say the open-time missing-font warning may still appear. Acceptance 5b decides whether that sentence changes.)
- The panel entry is `__acmEval` in `packages/panel-cep/host.jsx`; it serializes with `__acmJson`. See `AE-05` for a serializer bug on `TextDocument`. (Not reachable from `ae_run_script`: the wrapper refuses a host object before `__acmJson` runs.)
- Keep the script in one IIFE: `(function () { ... return value; })()`. (This applies to the script the builder sends; the caller's script may be a statement list.)

## Acceptance tests
Unit tests, against `test/ae-host.ts` (the `node:vm` stand-in for After Effects) and a fake panel, cover 1, 4 (runtime errors), 6, the refusal and the annotated envelope in 7, the shims and scope in 8, `args` round-tripping in 11, and the server's half of 2, 3, 5 and 10 (a stubbed `version`, one undo group around the script, the suppress calls, the timeout envelope). Everything else in 2–5 and 7–11 needs After Effects.
1. Gate off: `ae_run_script` and `cc_eval_script` appear in the tool list; calling either returns an `isError` text that `toContain(RAW_SCRIPTS_DISABLED_MESSAGE)`, and a connected fake After Effects panel receives no command.
2. Gate on: `ae_run_script({ script: "(function(){ return app.version; })()" })` returns a string. (ae-host has no `version`; the unit test stubs it.)
3. A script that creates two layers is undone by **one** Ctrl-Z, and the Edit menu reads "Undo <undoGroupName>".
4. A script that throws returns `{ message, line, bodyLine }` with `bodyLine` pointing into the user's script — a runtime error, a native error from a bad lookup, a `throw`, and a SyntaxError — with `line` equal to `bodyLine` at this nesting.
5. Dialogs (split; the original "with a project open and a missing font, `suppressDialogs: true` returns instead of hanging" promised more than is verified):
   - 5a. Save and export: with a project open whose text layer uses a font that is not installed, a script that saves the project and exports a Motion Graphics template shows the missing-font dialog with `suppressDialogs: false` (the call times out; the operator dismisses the dialog), and with the default `suppressDialogs: true` returns within a few seconds and leaves no dialog open. Record each dialog seen.
   - 5b. Open: `app.open()` of that project with `suppressDialogs: true`. Record whether the missing-font dialog appears. If it does not, the description and the `suppressDialogs` text drop "may still appear". If it does, record whether the `Hide Missing Font Dialog` preference (`General Section`, machine-independent) hides it and with which value, and restore the operator's value; only then does the model-facing text name that workaround, as a change the script makes and restores in a `finally` (in the `suppressDialogs` text if the description has no room within its 2,048 characters).
6. ES3 check: the builder passes `es3Violations`; the user's script is not scanned. (The test strips `asciiLiteral(script)` from the built text before scanning it.)
7. Managed calls: `app.beginUndoGroup("inner"); 1` is refused as plain text, nothing reaches the panel, and one `outcome=refused` audit line is written. A failing end call (provoked live with `app["end" + "UndoGroup"](); 1`) comes back as the annotated envelope with the script's value; record any mismatch warning and the Edit menu. After a throw (`app["end" + "UndoGroup"](); ({ get a() { throw new Error("g"); } })`, whose getter throws in the wrapper's result check) the note follows the thrown message in the dispatched envelope.
8. A bare `alert`, `confirm` and `prompt` in the script's own text fail the call with the shim's message, `line` and `bodyLine` `null`, and no dialog on screen. (Global code and `Window.alert` are not shimmed and would open a real dialog; do not probe them live.) `__args`, `__log` and the shims reach the caller's script; the After Effects helpers do not (`typeof __comp` is `"undefined"`). A script that puts data on `Object.prototype` is reported and the host healed; returning `app.project` is refused as a host object.
9. Project switch (run before 5): `app.project.close(CloseOptions.DO_NOT_SAVE_CHANGES); app.newProject(); 1` on a scratch project. Record whether the reply is ok or the end-call note, any dialog, and the Edit menu afterwards; also whether a save-changes prompt on `app.open()` of a dirty project is suppressed.
10. Timeout: a script that runs 8 s with `timeoutMs: 2000` gives the timeout envelope; an `ae_project_info` sent right after waits until the script ends; the undo group is closed afterwards.
11. `args` fidelity: plain data round-trips — a string with a quote, a backslash, `é` and U+2028; `1e21`, `5e-324`, `0.30000000000000004`; keys `default`, `""` and `constructor`. Object-literal keys `reflect`, `toSource` and `watch` enumerate as data in ExtendScript; any that do not are added to the encoder's refused keys.

Follow the test pattern in `00_PREAMBLE.md`.
