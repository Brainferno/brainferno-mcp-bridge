# X-03 — Test coverage and doc-drift guard

> Do this first: it makes every later prompt safer to build.

## Problem
1. **New tools are not automatically covered.** In `packages/server/test/after-effects-tools.test.ts`:
   - `SAMPLES` (about lines 41-96) lists exported script builders by hand.
   - The `__undo(` check uses a **hard-coded** list of 15 sample names (about lines 103-107); a new mutating tool is not checked unless someone remembers to add it.
   - The escaping check covers only 3 samples (about lines 109-113).
   - `ae_queue_render` builds its script **inline** in the registration (`after-effects.ts` about lines 1553-1565), so it is in no sample and gets no ES3 check; `renderCompHeadless` is likewise untested.
2. **Counts are hand-written and wrong in several places, and no test enforces them.** Tool-registration tests only `toContain` names (`server.test.ts:84-85,188`); no `.length` check; nothing in `scripts/` or `.github/workflows` verifies counts. The actual After Effects count is **34** (`registerTool("ae_` appears 34 times).
   - `README.md:19` "124 tools"; `:81` PS 21; `:88` AE **33**; `:98` PP 29; `:105` AI 7 (+46); `:111` AU 12; `:116` AME 6; `:121` audio 9; `:126` pipelines/jobs 8.
   - `README.md:346-354` table: `ps_` 18, `ae_` **24**, `pp_` 28, `ai_` 7, `au_` 12, `ame_` 6, `audio_` 9, `pipeline_` 4.
   - `docs/HANDOFF.md:16` "After Effects 24" (and PS 18, PP 28, AI 7, AU 12, AME 6, audio 9, pipelines 4, jobs 4); `:5-17` says `v0.2.2` is the current release (repo is v0.3.2); `:94-95` "Expect 127 tools".
   - `docs/spikes/14-release-process.md:98` "125 tools (ps 21, ae 32, pp 29, …)"; `docs/spikes/06-aftereffects-tools-live.md:33` "(24)"; `docs/spikes/11-remote-mode-and-installer.md:15` "116 tools"; `CHANGELOG.md:143` "After Effects 24".
   - `packages/server/README.md` repeats the numbers but is generated by `scripts/prepack-server.mjs:21`; fix the source.
3. **Other known drift:** `docs/spikes/06-…` shows `~/.adobe-cc-mcp/bridge.json` (the panel reads `~/.brainferno-mcp-bridge/bridge.json`); `docs/BUILD_PLAN.md:142` lists "MOGRT insert" as remaining though `pp_insert_mogrt` exists.

## Add
1. **Registry-driven tests.** Build the MCP server in-memory (the pattern in `server.test.ts`) and iterate over every registered tool per app. For each tool:
   - if it is **not** `readOnlyHint`, assert its script builder output contains `__undo(` (After Effects) or the host's equivalent wrapper (Photoshop `executeAsModal`, Premiere transaction);
   - assert the script passes `es3Violations` (ExtendScript apps);
   - assert string arguments are escaped by calling the builder with a value containing a quote, a backslash, a newline, and U+2028.
   Export the inline `ae_queue_render` and `renderCompHeadless` builders so they join the loop. Keep an explicit **allow-list** of tools that legitimately do not mutate (with a reason) so exceptions are visible.
2. **Generated counts.** Add `scripts/tool-counts.mjs` that counts `registerTool("<prefix>_` per `packages/server/src/tools/*.ts` file and prints the per-app and total numbers. Add a vitest that (a) runs the same count against the live registry and (b) fails if any number written in `README.md` or `docs/HANDOFF.md` disagrees.
3. **Remove hand-typed counts and versions.** Replace the lines listed above with a generated block between markers (for example `<!-- tool-counts:start -->…<!-- tool-counts:end -->`) that `npm run docs:counts` rewrites. Keep the version in the README's npm badge only (as the release notes already advise).
4. **Fix the other drift** listed in item 3 of the problem (path, stale BUILD_PLAN line; see also `X-01` for the env var name).

## Acceptance tests
1. Add a dummy mutating tool without `__undo(`: the registry test fails and names the tool.
2. Change `README.md:88` to a wrong number: the count test fails and prints the correct number.
3. `npm run docs:counts` rewrites the marked blocks idempotently (a second run changes nothing).
4. `ae_queue_render` is covered by the ES3 and undo loops.
5. `npm run typecheck && npm test` pass on Windows and macOS CI.
