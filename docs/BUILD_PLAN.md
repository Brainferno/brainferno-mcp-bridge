# Adobe Creative Cloud MCP Suite — Build Plan

## Context

Vince wants Claude to drive a full video + graphics production pipeline across the Adobe suite: **Photoshop, Illustrator, After Effects, Premiere Pro, and Audition** — all via MCP, as one unified system. End state: Claude orchestrates multi-app workflows (design in Illustrator → composite in Photoshop → animate in After Effects → cut in Premiere → mix audio → render), with in-app panels giving visibility and a kill switch.

User decisions collected:
- **Platforms:** macOS AND Windows — primary bridges must be cross-platform.
- **MVP priority:** Photoshop + After Effects + Illustrator first; then Premiere; then Audition.
- **Distribution:** personal/studio now (dev-mode installs fine); public later (signing/marketplace is a deferred phase).
- **Clients:** **Claude Code (CLI) first**; Claude Desktop deferred ("add desktop later"). stdio transport. This matters for the Illustrator-beta delegate below — Claude Code honors `tools/list_changed` and multiple side-by-side servers cleanly, where Claude Desktop currently discards `list_changed` until an app restart — so CLI-first lets us lean on dynamic tool availability now and add the Desktop-safe fallbacks (and the `.mcpb` bundle) later.

The repo (`brainferno/adobe-cc-mcp`, branch `claude/adobe-mcp-server-plugin-tnua0k`) already contains a real, tested **server half**: TS-strict stdio MCP server (`@modelcontextprotocol/sdk ^1.30`, `ws`, `zod`, vitest), WebSocket bridge on 127.0.0.1:7777 that panels dial out to (hello/welcome/eval/result JSON frames, protocol v1), 11 tools across 5 apps, 5 passing tests incl. a real fake-panel WS round trip. **No in-app panel code exists** — nothing can currently execute the scripts. A 9-agent deep-research workflow (Aug 2026, primary sources; findings archived in session scratchpad `synthesis.md` + `research-*.md`) settled the architecture below.

## Research verdict — per-app surfaces (Aug 2026)

**No single automation surface spans all five apps.** One MCP server with a pluggable per-app driver layer wins.

| App | Surface TODAY | Transport | Depth | Confidence |
|---|---|---|---|---|
| **Photoshop** (≥26) | UXP panel (manifest v5, apiVersion 2): modern DOM + `action.batchPlay` inside `core.executeAsModal` | Panel dials out as WS client to hub | Near-total (batchPlay = every recordable command) | High (proven: adb-mcp, dcc-mcp-photoshop) |
| **Illustrator** (≥CC2024) | **No public UXP.** Primary: ExtendScript DOM via OS bridge (`osascript 'do javascript'` / PowerShell COM `DoJavaScript`; temp `.jsx` + JSON marshaling) for create/save/full DOM. Plus optional **delegate** to Adobe's official beta MCP for analyze/batch/export | OS scripts — **no panel**; delegate = MCP client → `localhost:18412` | Complete classic DOM (ours) + Adobe's 40 analyze/batch tools | High (os-script proven; delegate is Beta-only) |
| **After Effects** (≥25.0) | CEP 12 panel (Node 17 inside) → `CSInterface.evalScript()` → ExtendScript DOM. **No AE UXP panels exist** | Panel dials out as WS client to hub | Complete (comps/layers/keyframes/expressions/renderQueue) + `aerender` CLI for headless renders | High |
| **Premiere Pro** (≥25.6) | UXP panel: `require('premierepro')` action model, typed via npm `@adobe/premierepro` | Panel dials out to hub; HTTP long-poll fallback on Windows (UXP localhost WS flaky there) | ~90% of timeline needs; CEP support ends ~Sept 2026 — **treat CEP as EOL, never build on it** | Med-High (API expands monthly; pin typings) |
| **Audition** (≥25.0) | CEP 12 panel (host `AUDT`) → undocumented ExtendScript DOM: `app.invokeCommand()` (~500 constants), Favorites, `saveAs()`, Transport, events. No UXP/COM/AppleScript/CLI | Panel dials out as WS client to hub | Menu-command depth; batch NOT scriptable → **ffmpeg/sox sidecar lane** carries deterministic/batch audio | Medium (Flue's audition_adapter proves the bridge) |

**Load-bearing platform facts:**
- **UXP plugins cannot listen on sockets** (client-only) → hub-that-panels-dial-into is mandatory and forward-portable. UXP WS **cannot set custom headers** → token via URL query or first-message auth with deadline. Manifest v5 `requiredPermissions.network.domains` needs the exact `ws://` endpoint (no wildcards since UXP 7.4; localhost bugs = uxp-photoshop #321; ws:// reliable, wss:// flaky).
- **Security threat model is real**: CVE-2025-52882 (unauthenticated localhost WS = drive-by from any web page; browsers exempt WS from same-origin) and CVE-2025-66414 (MCP SDK DNS rebinding). Hub must bind 127.0.0.1, require a random per-install token, validate Origin/Host, ignore frames from unauthenticated sockets.
- ExtendScript is ES3 (json2 polyfill; scripts block the app main thread). AE's "Allow Scripts to Write Files and Access Network" pref is only settable with AE closed; PlayerDebugMode lives under CSXS.12 for CEP 12.
- MCP practice: stay on SDK v1 (`^1.30`) — v2 is weeks old; zod `.strict()`; actionable `isError` text; previews as downscaled image blocks + `save_to_path` twins (client bug can serialize images as base64 text at 10–20× tokens); progress notifications reset Claude Code's idle `MCP_TOOL_TIMEOUT`; jobId+poll for >90s ops.
- Adobe's only official *desktop* MCP is Illustrator's built-in beta server (localhost:18412, analyze/batch/export only — no create/save/run-script); its cloud "Adobe for Creativity" connector is separate and Firefly/Express-level. No official desktop MCP exists for PS/AE/Premiere/Audition, so those lanes are all ours to build. **An Audition MCP would be the first anywhere.** The Illustrator beta is worth *incorporating* rather than reinventing — see the delegate-lane section below.

## Architecture (settled)

```
Claude (Desktop / Code)
   │ stdio (MCP, SDK v1)
   ▼
adobe-cc-mcp ─ one Node/TS process
   ├── WS hub (127.0.0.1:<port>, token auth, Origin/Host checks, heartbeat,
   │          per-socket pending, UUID correlation, per-class timeouts)
   │     ◄── dial-out panels: PS UXP · PPRO UXP · AE CEP · AU CEP
   ├── OS-script drivers: Illustrator (osascript / PowerShell COM,
   │          temp .jsx + JSON in/out) — also PS fallback lane
   └── Process drivers: aerender, Adobe Media Encoder, ffmpeg/sox
```

- Three driver lanes behind one `execute(envelope)` interface; namespaced tools `ps_* ai_* ae_* ppro_* au_* audio_* cc_* pipeline_*`.
- Previews: panel/driver **exports a file** → server downscales ≤1024px JPEG → MCP image block (+ `save_to_path` variant). Never UXP Imaging API (buggy), never megabase64 through the panel socket.
- App-not-connected = fast structured error with per-app remediation text, never a timeout.
- **Panels: two codebases, shared core.** bolt-uxp builds PS+PPRO variants; bolt-cep covers AEFT+AUDT — both consume shared `protocol` (types+zod), `bridge-client` (dial-out/auth/reconnect/heartbeat state machine, pluggable transport for the Windows long-poll fallback), `panel-ui` (connection badge, activity log, session counters, **kill switch** that closes the socket — severing the agent's only ingress). Command implementations are irreducibly per-app.

## Protocol v2 (freeze in Phase 0)

**Named commands on the wire, not raw script strings** — UXP restricts `eval` and Premiere UXP has no script engine at all, so panels map command names to local functions (adb-mcp's `command_packet` lesson). CEP panels use the same envelope; their registry includes generic `aeft.eval_jsx` / `audt.eval_jsx` commands (via `CSInterface.evalScript` — a host API, not JS eval) so server-side JSX templating keeps working; hot-path AE commands get promoted to named panel-side functions over time.

Frames (all zod-validated both ends; `PROTOCOL_VERSION = 2`, v1 dropped — no v1 panel ever shipped):
- `hello` (panel→server, ≤3s after upgrade): `{protocolVersion, appId, hostVersion, panelVersion, token?, capabilities: string[]}` — token also accepted as `?token=` on the upgrade URL.
- `welcome` `{serverVersion, heartbeatIntervalMs}` · `cmd` `{id, name, params, timeoutClass: "fast"|"slow"|"render"}` · `result` `{id, ok, value?, error?{code,message,line}, appState?{activeDocument,selection,dirty}}` · `progress` `{id, progress, total?, message}` · `ping`/`pong` · `bye`.

Hub rules: pending map **per socket** (result honored only on the socket its cmd went out on); auth state machine (any frame before valid hello → close 4001); token **required by default** — if unset, server generates 32 random bytes and persists `{token, port, pid}` to mode-600 `~/.adobe-cc-mcp/bridge.json`, which panels read (CEP fs / UXP localFileSystem) — solving token distribution AND port discovery; Origin/Host validation on upgrade; heartbeat every 15s, 2 missed → deregister + reject in-flight (`AppDisconnectedError`); close rejects that socket's pending; commands serialized per app (one ExtendScript/modal scope per host), concurrent across apps; `timeoutClass` → fast 10s / slow 120s / render → job registry; capability gating turns version drift into a structured "update the panel" error.

## Illustrator: incorporating Adobe's official MCP beta (delegate lane)

> **Live finding (2026-08-26, on-machine):** the delegate connected and enumerated **46 tools** (`docs/spikes/01-illustrator-beta-tools.md`). Adobe’s server does more than the research below says: it creates documents/artboards/layers/groups, moves/scales/rotates/restyles objects, replaces text/fonts, exports, previews, vectorizes, preflights. It still cannot **draw new shapes/paths/text** or **save a `.ai`**. Read “analyze/batch/export only” below as “everything except drawing new art and saving”. The os-script lane remains required for those two.

**What it is (verified Aug 2026, primary sources partly egress-blocked — treat specifics as needing on-machine confirmation):** Illustrator **(Beta) 30.4+** ships a built-in MCP server at `http://localhost:18412/v1/mcp` (Streamable HTTP, `MCP-Protocol-Version` unconfirmed), authed by a per-install Bearer key `ilst_<64hex>`. ~40 tools, **analyze/batch/export only** — document/color/font analysis, bulk/generative recolor, variations + datasets, batch artboard export, font/broken-link preflight. **Hard limits:** no create-document, no new objects/paths/text, no `.ai` save (export only), no run-script escape hatch. Runs only while Illustrator Beta is open with the feature toggled; the key persists across launches and changes only on manual regenerate. **Key discovery is UI-only** — copied from Illustrator's *MCP & Tools* panel; there is **no documented readable handshake file**, so our server cannot auto-discover it (unlike our own bridge). Exact tool *names* are not published — dump `tools/list` against a live server to enumerate.

This is exactly complementary to our os-script lane: **Adobe's server can analyze/batch/export but not create/save; our os-script lane can create/save/edit the full DOM.** So they compose into one Illustrator surface rather than competing.

**Two ways to incorporate (both viable under CLI-first):**
- **Model A — side-by-side (zero code, available today).** The user runs `claude mcp add --transport http --header "Authorization: Bearer ilst_<key>" --scope user illustrator http://localhost:18412/v1/mcp` and Adobe's tools appear alongside ours. Claude Code handles two servers fine. We just *document* this. Downsides: two overlapping Illustrator menus, the model must choose between lanes, our pipeline tools can't call Adobe's, and the key sits in the client config.
- **Model B — proxy/aggregation (recommended target).** `adobe-cc-mcp` acts as an MCP **client** to `localhost:18412` and re-exposes a *curated* subset of Adobe's tools under a `ai_adobe_*` namespace, behind one unified Illustrator surface. Verified feasible with the TS SDK: `Client` + `StreamableHTTPClientTransport(url, { requestInit: { headers: { Authorization: \`Bearer ${key}\` } } })` (static key goes in `requestInit.headers` — **not** an `authProvider`), then `client.listTools()` / `client.callTool()`. Implement the merge at the **low-level `Server`** (forward `tools/list` + `tools/call`) rather than per-tool `registerTool`, to avoid JSON-Schema→Zod round-tripping and the "registerCapabilities after connect throws" pitfall (SDK #893). Benefits: one coherent Illustrator toolset with **capability routing** (create/save/edit → os-script; analyze/batch/export → Adobe), pipeline tools can call Adobe's tools internally, and the secret stays server-side.

**Recommendation:** ship **Model A documentation immediately** (it works the day the os-script lane does, zero code), and **build Model B** as the strategic unification. Model-B specifics baked in:
- **Key handling:** user pastes the key once into our config — `ADOBE_CC_MCP_ILLUSTRATOR_KEY` env (or `~/.adobe-cc-mcp/config.json`, mode-600). Never logged, never sent to the model, never in error text. On `401` (user regenerated), fail with "re-copy the key from Illustrator ▸ MCP & Tools". No auto-discovery (no readable file exists).
- **Lazy connect, not startup probe:** Illustrator Beta opens/closes independently. Connect on first delegate call (and a light background re-check); cache the `Client`; on `ECONNREFUSED` mark unavailable with an actionable "open Illustrator Beta and enable its MCP server".
- **Availability UX:** register the delegate tools **unconditionally with graceful per-tool failure** (works on every client incl. future Desktop) **and** emit `sendToolListChanged` on open/close (Claude Code honors it; Desktop ignores it until restart — hence CLI-first). 
- **Curate, don't mirror all 40:** expose the high-value analyze/batch/export tools, suppress ones that duplicate ours or inflate context; keep raw `ai_adobe_*` as an escape hatch under unified `ai_analyze` / `ai_export` routers.
- **Beta churn caveat:** proxying a beta schema means re-mirroring when Adobe changes tools; pin/monitor the Illustrator Beta version and dump `tools/list` on each update.

## Step-by-step build plan

### Phase 0 — Harden bridge, fix engine map, freeze protocol v2 (existing flat package)
Cheap now, expensive after three panel codebases exist.
1. `src/apps.ts`: replace `engine` with per-app `{lane, panel?, scripting}` — photoshop `socket/uxp`, premiere `socket/uxp` (**remove** extendscript + appleScriptName; Premiere has no AppleScript/COM DOM), after_effects `socket/cep/extendscript`, audition `socket/cep/extendscript`, illustrator `os-script/extendscript` (+ `appleScriptName: "Adobe Illustrator"`, `winProgId`). Reroute `ai_list_documents` to the os-script driver interface (its current UXP snippet is wrong); mark `ppro_*` tools "pending UXP panel".
2. `src/bridge/protocol.ts`: protocol v2 frames + zod parsing (replaces the blind cast).
3. `src/bridge/socket.ts`: per-socket pending; auth state machine + 3s hello deadline; default-generated token + `~/.adobe-cc-mcp/bridge.json` handshake file (`ADOBE_CC_MCP_BRIDGE_INSECURE=1` debug-only escape); Origin/Host upgrade validation; app-level ping/pong heartbeat; disconnect rejects in-flight; only an authenticated hello may displace an existing panel (4004).
4. New `src/bridge/script-escape.ts`: `jsStringLiteral()` escaping quotes/backslashes/control chars **and U+2028/U+2029** (JSON.stringify leaves those raw = ES3 syntax error / injection); `renderQueueScript` switches to it.
5. Gate `cc_eval_script`: opt-in via `ADOBE_CC_MCP_ALLOW_RAW_SCRIPTS=1`, unregistered when off, restricted to ExtendScript hosts, every execution logged.
6. `src/config.ts`: handshake path, heartbeat interval, timeout classes, raw-scripts flag. Include `test/` in typecheck; expose a public `port()` on BridgeServer (kill the private-field reach-in in tests).
7. Tests (extend `test/server.test.ts`, new `test/bridge.test.ts`): auth matrix, pre-hello frames dropped+closed, rogue socket can't answer another socket's id, disconnect rejection, heartbeat expiry (fake timers), U+2028 round-trip, `cc_eval_script` hidden by default.

**Exit:** adversarial tests green; v2 documented in `docs/protocol.md` and **frozen** (post-freeze changes go through the protocol-guardian review below).

### Phase 1 — Validation spikes, in priority order (throwaway code in `spikes/`; results in `docs/spikes/NN-*.md`)
Run on the user's real macOS + Windows machines (Claude Code drives, human clicks in the apps). Order = least sunk cost invalidated first.

1. **UXP localhost WS, both OSes** *(gates the hub design → spike #1)* — bare bolt-uxp panel in PS **and** PPRO dialing the Phase-0 hub. Hazards: `network.domains` localhost "Permission denied" (uxp-photoshop #321); adb-mcp forces HTTP long-poll on Windows. **Exit:** hello→cmd→result round-trip in PS+PPRO on mac **and** Win; matrix `ws://127.0.0.1` vs `ws://localhost`; token-in-query vs hello-frame; reconnect-after-restart. **If Win WS fails:** hub grows an HTTP long-poll endpoint (`POST /v2/poll` + `/v2/result`, same frames/auth) and `bridge-client` gets a transport interface (`wsTransport`/`pollTransport`) — frames and tools unchanged. **→ Spike 1 Windows leg GREEN 2026-08-26** (`docs/spikes/03-photoshop-uxp.md`): works with `domains: "all"` (explicit `ws://127.0.0.1:PORT` rejected), hub must accept `Origin: file://`, `new Function` blocked → named commands mandatory. No Windows long-poll fallback needed. macOS + Premiere legs still to run.
2. **AE CEP round-trip** — bolt-cep panel (host AEFT, CSXS 12, `--enable-nodejs --mixed-context`) → hub → `evalScript` → json2-polyfilled JSX → JSON. **Exit:** <500 ms trivial round-trip; error+line propagation from a throwing JSX; then `app.project.save()` + spawn `aerender -project … -comp … -output … -mfr` with stdout progress parsed. Documents PlayerDebugMode (CSXS.12) + the "Allow Scripts to Write Files and Access Network" pref (only settable with AE closed). Both OSes.
3. **Illustrator OS bridge** *(no panel)* — server spawns `osascript -e 'do javascript'` (mac) / PowerShell COM `DoJavaScript` (Win) with temp `.jsx` + JSON param file in, JSON result file out. **Exit:** create→draw rect→export PNG on one **CMYK** and one **RGB** doc (validates coordinate normalization); macOS TCC Automation-prompt flow documented (grant once from an interactive terminal, then works from a Claude-spawned server); Windows works with the versioned ProgID. **→ Windows leg GREEN 2026-08-26** (`docs/spikes/02-illustrator-osscript.md`): COM lane draws, previews, saves; macOS leg still to run.
4. **Premiere UXP coverage** — script the top-10 timeline ops against `@adobe/premierepro` (26.3 stable + 26.5 beta): insert/overwrite at TickTime, remove-with-ripple, set in/out, transition, effect+keyframe, MOGRT insert, marker, export frame, export sequence, QUEUE_TO_AME. **Exit:** a written gap list with a per-gap decision — *accept* / *MOGRT workaround* / *FCPXML·OTIO roundtrip*. A CEP shim is explicitly NOT an option (EOL).
5. **Audition DOM dump** — load Adobe's ScriptDictionary + ApplicationCommands samples on AU 26; dump the API to `docs/api-dumps/audition-<ver>.txt`; CEP panel fires `app.invokeCommand` on a pre-recorded Favorite. **Exit:** panel loads; a Favorite applies an effect chain **without a modal**; `WaveDocument.saveAs()` exports; `isCommandEnabled` gating verified across Waveform vs Multitrack. If modals block → AU shrinks to open/save/transport/Favorites and ffmpeg carries the rest.
6. **Preview economics** *(piggyback on 1–3)* — export → downscale ≤1024 px → JPEG → MCP image block in Claude Desktop **and** Code; record per-preview token cost, confirm the image-as-base64-text client bug's blast radius, pick the default size, confirm `save_to_path` twins.
7. **Dev-install persistence** *(alongside 2)* — confirm UDT loads die on app restart (expected) and an installed dev `.ccx` / symlinked CEP folder survives; document the per-app dev-loop.

**Exit:** spikes 1–3 green (gate the MVP apps); 4–5 produce decision docs (gate Phase 4 scope). Any red spike triggers its named fallback and updates `docs/spikes/`; only a *transport* change (not frame format) may amend the frozen protocol.

### Phase 2 — Monorepo migration (after spikes 1–2, before production panels)

### Phase 3.5 — Illustrator delegate lane: incorporate Adobe's official beta MCP (Model B)
Small, self-contained, independent of the panel/hub work — buildable now (Vince has Illustrator Beta live with a working key). New `src/drivers/illustrator-delegate.ts`: an MCP `Client` over `StreamableHTTPClientTransport` to `http://localhost:18412/v1/mcp` (default), Bearer from `ADOBE_CC_MCP_ILLUSTRATOR_KEY` env or `~/.adobe-cc-mcp/config.json` (mode-600). Key is held privately — never logged, never in error text, never sent to the model. **This runs on the user's machine, not in a remote/cloud session** (the Beta server is on their localhost); CI verifies the wrapper against a stub, the live call is a local step.

**First cut — discovery + passthrough (implement now).** Adobe's ~40 tool names/schemas are unpublished and a moving beta target, so instead of mirroring them we track them at runtime with three tools (registered only when a key is configured):
- `ai_beta_status` (read-only) — reachable? tool count? Lazy-connects; never throws.
- `ai_beta_list_tools` (read-only) — the downstream tools' names + descriptions, so the model can pick one.
- `ai_beta_call` — forward `{tool, arguments}` to Adobe and return its result verbatim (text/image blocks pass straight through). Actionable "open Illustrator Beta / enable MCP & Tools / re-copy the key on 401" error when unreachable.

Lazy connect (Illustrator opens/closes independently), cache the client, reset on any error so the next call reconnects.

**Follow-on — curated first-class re-export (optional, later).** Once the real 40 are enumerated on-machine, re-expose the high-value ones under `ai_adobe_*` (low-level `tools/list`+`tools/call` forward, prefix-stripped) with `sendToolListChanged` on connect/disconnect (Claude Code honors it), and unified routers (`ai_analyze`, `ai_batch_export`, `ai_recolor`) that dispatch create/save → os-script, analyze/batch/export → Adobe. Pipeline tools (Phase 5) can then call the delegate internally.

**Tests:** inject a fake `DelegateClient` (the driver takes a `clientFactory`) to exercise lazy-connect, caching, reconnect-after-failure, passthrough, and the unavailable→actionable-error path — no HTTP/real Illustrator in CI. Registration test: `ai_beta_*` present when a key is set, absent when not.
**Exit:** unit suite green; with a key set the three tools advertise and, against a fake downstream, round-trip; with no downstream they return the actionable message. On Vince's machine: `ai_beta_status` reports reachable and `ai_beta_list_tools` dumps the real 40 (recorded in `docs/spikes/`); then rotate the key (it was shared in chat).

### Phase 4 — Premiere (UXP) + Audition (CEP + ffmpeg lane)
- **Premiere `ppro_*`** — `panel-uxp` gains the PPRO variant; tools against `@adobe/premierepro` (pin exact version, re-test per dot-release, capability handshake gates tools by API availability in `hello.capabilities`): project (info/list_sequences — both rewritten on UXP/open/import_media/list_project_items/create_sequence_from_media); timeline via action model + compound actions for single undo (insert/overwrite/remove-with-ripple/set_in_out/add_marker/add_transition/apply_effect/set_effect_keyframes/insert_mogrt); export (export_frame→block / export_sequence IMMEDIATELY·QUEUE_TO_AME→jobId / export_fcpxml·otio); differentiator `ppro_transcribe` (Transcript API). ### Phase 5 — Cross-app pipelines, job registry, progress
1. **Job registry** (`src/jobs/`): ids, states (queued/running/succeeded/failed/cancelled), progress %, artifact paths, log tail; tools `cc_job_status`, `cc_list_jobs`, `cc_job_cancel`; anything >~90 s returns a jobId immediately.
2. **Progress notifications**: panel `progress` frames and process-lane stdout both forward to `notifications/progress` against the client's `progressToken` (resets Claude Code's idle timer); emit every few seconds during renders.
3. **Shared work-dir**: `~/.adobe-cc-mcp/work/<jobId>/` for cross-app handoffs, with cleanup policy.
4. **Pipeline tools** (the product): `pipeline_ps_to_ae`, `pipeline_render_and_import` (AE→aerender→Premiere import), `pipeline_audio_roundtrip` (Premiere audio→ffmpeg→reimport), `pipeline_ai_to_ps` — each a driver composition inside one tool call with per-step progress and a structured failure report naming the step + recovery tool.
5. Optional dynamic tool exposure via `sendToolListChanged` as panels connect/disconnect, keeping the always-advertised + structured-error behavior underneath (clients handle `list_changed` unevenly).

**Exit:** the flagship pipeline — PS asset → AE animation → aerender → Premiere timeline → ffmpeg audio → back to timeline — runs from one Claude conversation with visible progress and no timeout babysitting.

## Risks & mitigations (top 8)
1. **UXP localhost WS flaky on Windows** → Spike-1 Win leg fails → hub HTTP long-poll transport + `bridge-client` transport interface; frames/tools unchanged.
2. **Premiere UXP gaps block useful v1** (Essential Graphics text, captions, razor) → Spike-4 red items → per-gap MOGRT workaround / FCPXML·OTIO roundtrip / documented "not supported"; never a CEP shim (EOL).
3. **AE onboarding friction** (PlayerDebugMode CSXS key; file/network pref settable only with AE closed; macOS TCC) → Spike-2 cold start >30 min → `installers/` + `doctor` preflight; last-resort Dakkshin-style file-polling ScriptUI lane kept documented.
4. **Audition DOM too shallow / modal commands** → Spike-5 → shrink AU to open/save/transport/Favorites; ffmpeg carries all batch (built regardless).
5. **Illustrator OS bridge breaks** (`do javascript` regression; TCC never prompted; COM wrong version) → Spike-3 / version-check → hard error naming the known-good range, interactive TCC grant, versioned ProgID; last resort a CEP ILST panel reusing `panel-cep` (lane abstraction makes it a swap).
6. **Hub security regression → drive-by script execution** (CVE-2025-52882 class) → adversarial CI fails / reviewer finding → token mandatory + Origin/Host validation + per-socket pending are *tested invariants*, raw-script tools off by default, release blocked on `/security-review`.
7. **Server↔panel version drift** (named commands need lockstep) → `UNKNOWN_COMMAND` / `adobe_status` shows old panelVersion → `capabilities` gating turns drift into a structured "update the panel" error, never a hang; protocol frozen with a guardian; panel semver in the UI.
8. **Preview/token economics** (image-as-base64-text bug 10–20×; big canvases) → Spike-6 measurements → downscale ≤1024px JPEG, `save_to_path` twin on every preview, pipelines pass file paths.

*Watchlist (`docs/risks.md`):* **a second server instance cannot start** — the bridge port is fixed, so a second `adobe-cc-mcp` (e.g. `claude mcp get`, or a second Claude Code session) dies with `EADDRINUSE` (seen on-machine 2026-08-26; the first instance keeps working). Fix later: fall back to an OS-assigned port and a per-instance handshake, or refuse cleanly with a clear message; CEP-12 removal ever announced for AE/AU (topology already UXP-shaped → changes the panel, not the hub); default port collision (handshake file makes port dynamic — default moved to 7897 in Phase 0); `@adobe/premierepro` beta breaking changes (pin + re-test per dot-release); Windows-on-ARM Audition CEP behavior; **Illustrator-beta delegate** — Beta-only (30.4+) so absent on stable Illustrator (os-script lane still fully covers create/save/export, so the delegate is pure upside); beta tool-schema churn (re-mirror on Adobe updates); key is user-pasted (no readable file to auto-discover) and rotates on manual regenerate → handle 401; Adobe may promote it to stable and/or add create/save, which would let us retire parts of the os-script lane.
